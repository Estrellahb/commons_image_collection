# 公开材料、作者记录与交付契约

## 交付目录契约与信息隔离

单题成果严格区分为**最终交付目录**与**过程工作目录**，禁止将中间脚本、JSON 或报告混入最终交付目录：

1. **最终交付目录 `outputs/authoring_<题号>/`（严格只存放 2 个文件）**：
   - `干净原图文件`：实际提交给答题模型的完整清晰原图（不叠作者编号、红点或答案文字）。
   - `author_record.html`：单文件自包含作者记录与审阅页。
2. **过程工作目录 `outputs/_work/<题号>/`**：
   - `solver.py`、`facts.json`、`recompute.json`、`manifest.json`、`qa_report/`、`eval_4x.json`、`review.json`、临时裁图与渲染脚本等全部过程材料统一存放在此目录。

发给模型试答（如 `eval_trials.py`）的公开输入只取干净原图与 `prompt`（以及题面内必需的公开参数与输出格式），绝不把 `thinking`、两段作者解答、`response` 或来源备注送入模型上下文。

来源信息保留在作者记录和许可要求的署名位置。不能为防检索而抹掉必要署名，不能微扰真实数据后仍叫原始观测。可以把任务对象去身份化，但必须明确任务新增状态、坐标变换和条件。

## `author_record.html` 必备自包含内容

`author_record.html` 需无外部运行时依赖（字体、样式、打点对照、复制脚本内联或纯本地可读），完整包含以下区块与按钮：

| 区块/字段 | 必须包含的内容 |
|---|---|
| 基本信息表 | `id / version`、题名、一级题型、难度、`图片大类 / 小类`、原图宽高尺寸（`W × H`）与素材类型、来源与作者、许可条款及是否修改说明，并配**一键复制按钮** |
| 原图与 1–3 个打点对照图 | 左侧展示干净原图，右侧展示仅标注 **1–3 个**最有价值视觉证据点的对照图，并列出各点原图像素坐标 `(x, y)`、标签与理由 |
| `prompt` | 纯公开题面：最少必要条件、完整判据、递进小问、单位、空集/并列规则与输出格式，配**一键复制按钮** |
| `thinking` | 出题思路：哪个图像区别改变哪条关系/参数并影响哪个答案字段，以及为什么该图适合此题，配**一键复制按钮** |
| `cot_image_understanding` | 第一段作者解答：逐对象/格子/刻度写全求解所需的必要读数、位置坐标与干扰辨析，配**一键复制按钮** |
| `cot_reasoning` | 第二段作者解答：从第一段读数和公开规则推导关系、计算、去重、最优/并列及标准答案，配**一键复制按钮** |
| `response` | 标准答案（唯一标准或公开定义的等价规范结果），配**一键复制按钮** |
| 逐字段判分口径 | 每一小问/字段的数据类型、单位、数值容差、有序/无序、固定宽度编码前导零与并列规范 |
| 质检与复算摘要 | `inspect_images.py` / `review_case.py` 审阅结论、正确输入与合理误读反事实复算对比、`eval_trials.py` 4 次直调结果与难度判定 |

## 平台字段对照与素材要求

已存平台八种主类：`计数聚合链`、`游戏／谜题规则求解`、`复杂指令遵循`、`小众知识解码`、`抗干扰文本读取`、`定位度量`、`拓扑／图结构追踪`、`空间变换`。图片大类另有实拍密集场景照、规则盘面图、程序合成谜题图、拼贴复合图、实拍文字载体照、图示与专业记谱、软件界面截图。最终词条以当次填报页面为准。

- **不设图片尺寸/1080p 硬门槛**：本项目已彻底取消 `1080×1920` 原生分辨率及文件体积/最小像素阻断规则（包括 BBBC039 等低分辨率科学图均可正常入库出题）。仅如实记录图像实际宽高 `W × H` 与素材类型，并在原图 100% 视图下人工确认必要细节清晰可辨。
- **语言与文字**：按采集要求避开大面积无关中文干扰图；用于识别、定位或计数的图内文字线索优先英文，或使用明确数字、位置和图例。题干语言单独按交付要求确定。OCR 中文面积仅辅助筛选，不为删去许可署名提供理由。
- **两段作者解答**：均须给审题人完整阅读，不能只写“见图/见代码”。第一段中的关键事实应能追到图中位置；第二段应能从第一段独立复算，不凭空引入私有判据。多小问输出固定顺序，整数、实数容差、无序集合、固定宽度编码分别比较，避免把 `3` 和 `3.0` 当作能力差异。

## 打点规范

1. 以最终原图左上角为原点，坐标满足 `0 ≤ x < W`、`0 ≤ y < H`，记录像素坐标 `(x, y)`，HTML 叠加标注可用百分比 `100x/W`、`100y/H`。源图若经合法裁切、旋转、缩放或拼贴，须映射至最终图片坐标。
2. 查看点附近原尺寸区域，确认点落在目标细节上、没有指到遮挡前景或相邻对象，且不遮住被考关键像素。点是否精确取决于特征本身大小，不给所有图强加固定容差或固定裁窗。
3. 平台与 `author_record.html` 打点图只保留 **1–3 个**最关键证据点（含点号、像素坐标、对象/属性与理由）；完整逐对象事实表与全量坐标保存在 `outputs/_work/<题号>/facts.json` 中（若为极精细全量核验，可在 `author_record.html` 文本表中列出摘要或附于工作区），不要把几十上百个点全堆到平台对照图上。

## 多层次依赖与空集

为每个输出记录 `fact IDs → 参数/关系 → 答案字段`。去除某面板或将关键事实替换成合理混淆读法后，主问应有可观察变化（并在 `outputs/_work/<题号>/recompute.json` 中保存实际重算前后对比）；这不要求对每个背景对象都敏感。后续推理应真正消费前期视觉事实，但允许模型一次完整转录所有事实后再求解。

如果可行集为空而题目只问数量，`0` 是有效答案；若还问最大值/最优代表，则必须公开约定空集返回值或修改实例。并列可以定义返回全部、最优解数或字典序规范代表。检查空集、并列和相同赢家是否使本题宣称的考点退化。

## 审阅与台账回写

- 运行 `python3 skills/zerobench-visual-benchmark/scripts/review_case.py --case outputs/authoring_<题号> --out outputs/_work/<题号>/review.json` 直接对 `图片 + author_record.html` 交付目录做只读审阅。
- 定稿或决定淘汰后，及时通过 `python3 skills/zerobench-visual-benchmark/scripts/sqlite_ledger.py mark` 回写 `采集数据.sqlite` 中的 `authored_status`（`authored` 或 `discarded`）与 `authored_ref`。
- 提交平台、修改外部表格和向其他应用发消息各按用户授权执行。
