# 评测、归因与停止规则

## 运行合同（`.env` OpenAI 兼容接口 4 次直调）

当前工作区默认使用本地 Python 直接调用 OpenAI 兼容接口进行评测，**无需启动 Colima 或 Docker 容器**。运行前先确保在项目 `.env` 或环境中配置：

```dotenv
OPENAI_BASE_URL=...
OPENAI_API_KEY=...
```

API Key 仅保存在 `.env` 或环境变量中，绝不写入 skill 文档、`outputs/authoring_<题号>/`、图片或公开日志。

标准评测命令（在项目根目录用 `python3` 执行）：

```bash
python3 skills/zerobench-visual-benchmark/scripts/eval_trials.py \
  --case outputs/authoring_<题号> \
  --out outputs/_work/<题号>/eval_4x.json
```

默认参数与行为契约：

- **默认模型与推理档**：`--model gpt-6.2-sol --effort max --trials 4 --api auto`（`reasoning_effort="max"`）。
- **协议自适应**：`--api auto` 自动兼容 `/v1/responses` 与 `/v1/chat/completions`，向模型发送干净原图与公开 `prompt`。
- **纯模型直答（无本地代码工具）**：默认 4 次试答均为**纯模型直答，不挂载本地代码工具**（不接 Python、容器或外部工具调用）。
- **产物隔离**：评测结果与完整回执写入 `outputs/_work/<题号>/eval_4x.json`，严禁写入 `outputs/authoring_<题号>/`。
- **`local_runtime.py` 与 `assets/docker/` 仅作可选保留**：如未来有明确授权需要对比工具开放环境，再显式接入并在报告中分开标注 `no_tools=false` 与实际可用工具清单，不得与纯模型直答结果混淆。

## 四轮完成与难度合格标准

- **完整 4 轮试答**：默认每题完整运行 4 个独立逻辑试次（`--trials 4`），不因首轮答错而悄悄中断其余轮次。若用户明确要求节省型首错停筛选，须单独记录 `skipped_early_stop`，不得把未跑轮次混作已测或统计为 `4/4` 失败率。
- **难度合格标准（错 ≥ 1 次即合格）**：
  - 在 4 次有效可判分试答（排除服务/传输异常、超时、残缺输出及内容缺陷）中，**只要有 ≥ 1 次未答对（`incorrect >= 1`，即非 4/4 全对）即判定难度合格**。
  - 若 **4/4 全对**（`correct == 4, incorrect == 0`），则当前版本难度未达标，需进入提难返修或淘汰该候选图/题型。
- **有限返修上限**：初版（`v1`）之后**最多允许两次实质返修（`v2`、`v3`）**，且前提是题面与 GT 本身无内容缺陷。同一题在无内容缺陷的前提下若已确认难度合格（`incorrect >= 1`），无需继续消耗后续返修预算；若 4/4 全对且缺乏新的可核验视觉区分机制，应果断淘汰并回写 `discarded`。

## 状态分开保存

| 状态 | 含义 | 能否计入有效错答（`incorrect`） |
|---|---|---|
| `correct` | 完整末答按公开判分口径正确 | 否（计入 `correct`） |
| `incorrect_candidate` | 完整末答与 GT 不同，尚待内容复审 | 尚不能，须先复审排除题目缺陷 |
| `confirmed_model_error` | 公开规则可解、GT 可信、判分公平、配置回显相符的有效错误 | 可以，计入 `incorrect` 并归因（视觉/关系/计算/未定位） |
| `content_invalid` | 错图、GT 错、隐藏计分、定义缺失、图不可判或答案泄露 | 不可以；同版本相关试次均不得算难度达标，修完重测 |
| `quality_ineligible` | 来源许可或核心细节清晰可辨性不满足要求（注：已取消 1080p 分辨率硬门槛） | 不可以作为正式合格题；不与数学无效混为一类 |
| `needs_review` | 末答解析格式歧义、等价解待确认或证据不足 | 尚不能，复核后重判 |
| `budget_exhausted` / `model_incomplete` | 达到长度/超时限制、残缺输出、无完整可判分终答 | 不可以；单列统计，不计入 `incorrect` |
| `service_or_transport` | API 连接、HTTP 5xx/429、网关超时、断连 | 不可以；单列基础设施故障，允许按授权补测 |
| `cancelled` / `skipped_early_stop` | 用户中止或筛选模式跳过 | 不可以 |

注意：若响应异常落入超时字段（如 `WriteTimeout`、`Broken pipe`、网关断流），须核对底层异常来源，不能误归因为模型推理错误；无完整可判分答案时，不可直接充当难度合格依据。

## 错答复审

1. **对齐冻结版本**：核对 `outputs/authoring_<题号>/` 中的干净原图、`prompt`、`response` 及逐字段判分口径与 `eval_4x.json` 中的请求模型/推理档回显（`gpt-6.2-sol`、`max`）一致。
2. **核查等价表达与题目缺陷**：接受公开规则允许的等价数值表达（如 `3` 与 `3.0`），保留固定宽度编码前导零，按公开规则核对无序集合、空集与并列分支；确认 GT 与公开条件无隐藏豁免或定义缺失。
3. **归因视觉或推理错误**：阅读模型最终输出中的视觉转录与推理过程，把模型实际采用的错误视觉读数代入 `outputs/_work/<题号>/solver.py` 复算；若能复现对应字段错误，则记为具体的视觉/绑定失败链。
4. **未定位错误不编造**：若模型只给出终答或内部读图未展开，仅如实记录错误字段与数值差异，不从最终差 1 反推“一定看错了某个点”。

## 返修、恢复与批次统计

- 更换核心图片、关键规则或答案语义时升级版本（`v1 → v2 → v3`），保留历史版本工作目录 `outputs/_work/<题号>-v1/` 等用于追踪，不通过改题号悄悄重置返修次数上限。
- 若因网络或限流中断只完成了部分试次，仅补齐受影响试次并保留原始回执；不删除失败记录来美化统计。
- 批次汇总至少区分：计划题数/试次数、有效完整试次、`correct`、有效 `incorrect`（及按题汇总的达标题数：`incorrect >= 1`）、`content_invalid`、待复审、服务/超时中断。题目产率 = 确认难度合格且内容无缺陷的题数 / 实际进入该批的候选题数，不与试次通过率混淆。
