# ZeroBench 图片与视觉依赖质检

目的：找到可辨认、可标注、来源适用，而且关键视觉差异能改变答案的图片。图片复杂度、逻辑复杂度、来源合规和模型实测证据分别记录。高熵、高目标数、高分辨率或一次错答均不能独自证明达标。

## 工作流程

1. **接收素材和适用要求。** 记录来源、图号或帧号、原始大小、许可、变换历史及场景 ID。区分真实照片、真实观测、真实结构数据渲染、题设示意图、模拟观测。以真实序列模拟出的凝胶仍是模拟图；软件画出的晶胞可作为结构数据渲染。组合图逐面板登记。用户指定真实原图时，不用模拟实验图顶替。
2. **机器提候选，人工验关键证据。** 对照[指标与输入格式](references/metrics-and-schema.md)，运行 `scripts/inspect_images.py MANIFEST --out REPORT_DIR`。使用已有 Pillow/NumPy 环境，不自动装包或下模型。COCO/YOLO 提供候选框；人工检查分类、合并碎片、重叠、镜像和真正遮挡。没有框时输出未知，不把边缘或纹理当目标计数。
3. **按类型筛图，不做统一复杂度总分。** 优先真实货架、显微和多时相图中可辨识的近似对象、多属性对应、跨区域排除证据。结构数据渲染适合周期邻居、层别及配位；科学网络图适合连接和状态，不能把排版距离当物理长度。[图源优先级与边界](references/source-priorities.md)
4. **检查图到答案的依赖。** 为每问记录对象、ROI、读数、控制的参数和输出。后续阶段应消费新的必要图证，例如另一层的身份、价签或边的状态。增加小问却只复用第一问抄出的表，不增加视觉证据需求。“多区域依赖”不等于证明模型实际多次回图；允许一次完整、正确的读图和编程求解。
5. **测距稳健、误配敏感。** 声明像素投影距离、标定物理距离或沿边距离。正常读数误差不跨阈值，合理的错误配对要改变关键输出。让作者求解器重算正确读法与混淆读法，保存字段级结果。如果主问是反转，检查反转位，而不只检查中间成本变动。不要把阈值刻意放在不可辨认范围制造假难。
6. **检查可绕过路径。** 审查题面和图中文字是否泄露对应关系或终值；看只读一个大裁图/简单查表/识别现成题源是否绕过设计中的关键图证。允许工具，不将计算量大、矩阵求逆或枚举慢当视觉难点。真实但简单的读图题降低投入；普通程序求解仍必须正确提取视觉事实的题不因此无效。
7. **输出分层结果。** `blocked` 有明确冲突；`needs_review` 有关键未知；`authoring_candidate` 仅表示已登记复核项齐备，不代表平台通过或高难实测。平台打点仅 1–3 个关键位置，完整作者事实表另存。两段解答分别写必要读图事实、约束计算。只有轨迹明确定位到错读才标“模型误读点”，否则标作者关键证据点。

## 与既有实测对齐

读取[案例证据和返修规则](references/evidence.md)。固定题版、工具条件和有效作答分母；超时、连接错误、未完成向量单列。旧的 `no_tools=true` 错答不算工具开放条件的达标证明。题面、图或关键规则变化后，旧轨迹仍属于旧版。

用户只要筛图、skill 或代码时不启动模型评测。需要评测时按用户最新授权执行并保留工具可用设置，不因求解困难限制工具。三轮加难后仍无有效错答的方向按用户当前淘汰要求处理；在没有新的试答证据时只提出替换建议，不虚构淘汰结果。

## 协作分工

用户授权多 agent 时，来源/图片审查、题目与测距依赖审查、GT/失败归因审查可独立分工；整合时保留争议和未知。协作前核实实际会话身份，不能把共享目录或其他模型的发言冒称 Gemini 已确认。仅写新质检目录，避免覆盖正在生产的题包。
